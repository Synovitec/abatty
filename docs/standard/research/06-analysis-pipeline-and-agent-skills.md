repositories' own READMEs, docs and manifests on that day (`gh api`), versions from the npm
registry, and one behaviour from a real headless session on the machine that runs the nights.

## 3. The skill rating table, against what runs here

The table rated eight skills five to four stars generically. The engine rates by whether a
skill can run unattended: `tdd`, `code-review`, `diagnosing-bugs` run at night;
`improve-codebase-architecture` and `grill-with-docs` are daytime rows with the ADR caveat
(their ADRs go where the repository keeps decisions, with the house front matter, or the docs
gate is red); `grill-me`, `triage` and `ask-matt` are never in a night (the night's grilling is
§9; the tracker is not a work queue on a client project; the router is §8's "use it when").

## 4. What is deferred, and the measurement that decides it

A code server (Serena first, codedeep-mcp after) enters a night only as an A/B: one phase with
it and one without on the same repository, cost and outcome from the runner's JSON. Before the
A/B: declared in `mcp.night.json` and `adoption.json → mcpServers`; a custom context (not the
"Read FORBIDDEN" one, which fights the hooks); `no-memories,no-onboarding` at night; `.serena/`
under `protectedPaths`; the reviewer agent's `tools:` limited to the read tools.
